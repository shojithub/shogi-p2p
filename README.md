# P2P将棋（IPv6優先・サーバーレス対戦）

GitHub Pagesに置くだけで遊べる、WebRTC P2P対戦将棋です。ゲームサーバーは不要です。

## 遊び方

- **ランダム対戦**: 「ランダム対戦を探す」を押した人同士が自動でマッチングします
- **あいことば対戦**: 同じあいことばを入力した2人が対戦できます
- **対面2人対戦**: 同じ画面で交互に指すモード
- **CPUと練習**: ランダムに指す簡易CPUとの練習モード

操作: 自分の駒（または持ち駒）をクリック → 緑の点が出たマスをクリック。成れる場合は「成る／成らない」を選べます。

## GitHub Pagesへの置き方

1. GitHubで新しいリポジトリを作成（例: `shogi-p2p`、Public）
2. このフォルダの `index.html` / `shogi.js` / `net.js` をリポジトリ直下にアップロード
3. リポジトリの Settings → Pages → Build and deployment → Source: **Deploy from a branch**、Branch: **main / (root)** を選んで Save
4. 数分後に `https://<ユーザー名>.github.io/shogi-p2p/` で公開されます

## 仕組み

- **マッチング/シグナリング**: 公開MQTTブローカー（EMQX公開ブローカー、接続できない場合はHiveMQ公開ブローカー）を使用。ロビートピックで対戦希望者を募り、ペアが決まったら専用トピックでWebRTCのSDPを交換します
- **対戦データ**: WebRTC DataChannel でブラウザ同士が直接通信（P2P）。指し手はすべて端末間で同期され、相手の手は自端末のルールエンジンで検証してから適用します
- **IPv6優先**: 自分のSDPに含まれるICE候補（candidate）を IPv6 → IPv4 の順に並べ替え、IPv6候補の優先度値を高く書き換えてから相手へ渡します。これによりICEの候補ペア選択がIPv6へ誘導されます。ただし候補の生成と最終選択はブラウザのICE実装が行うため「優先」であって強制ではありません。実際に選ばれた経路（IPv6/IPv4、host/srflx）は接続後に画面上部に表示されます
  - MAP-E（v6プラス）などIPv6ネイティブな回線同士では、IPv6のhost/srflx候補で直接つながりやすい構成です
  - STUNは Google / Cloudflare の公開STUNを使用。TURNは使っていないため、NATの組み合わせによっては直結できない場合があります

## ルール実装

- 全駒の動き、成り（強制成り含む）、持ち駒の打ち
- 二歩禁止、行き場のない駒（歩・香を最終段、桂を最終2段へは不可）
- **打ち歩詰め禁止**（歩を打って詰ませる手は指せません）
- 王手・詰み判定（詰み／行き詰まりは手番側の負け）
- 千日手: 4回目の同一局面で引き分け。ただし一方が王手をかけ続けた千日手は、その側の反則負け
- 入玉宣言法は未対応です

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` | 画面と対局進行（単体で完結するUI） |
| `shogi.js` | 将棋エンジン（合法手生成・王手/詰み・打ち歩詰め判定） |
| `net.js` | MQTTマッチング + WebRTC + IPv6優先SDP処理 |
| `test-engine.js` | エンジンの検証（`node test-engine.js`） |
| `test-ui.js` | 画面操作の検証（要 `npm i jsdom`、`node test-ui.js`） |

外部ライブラリは mqtt.js（CDN）のみ。その他は素のJavaScriptで、ビルド不要です。
